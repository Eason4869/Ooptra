# 三渠道文件同步审查与修复

目标：保持 main／beta／dev 的功能一致、既有版本号不变，修复遗漏更新的预览及审查发现的真实缺陷。

1. 以 Git 跟踪清单为范围，比对三个渠道，分组审查运行代码、示例、入口、前端、测试、CI、资源和文档。历史设计与发布记录保留原语境。
2. 从当前 WebUI 的 HTML、CSS、JS、品牌资源和配置白名单生成独立预览，隔离演示操作与真实后端；补齐登录、导航、语音、更新备份演示。
3. 增加生成检查及离线浏览器验证，使以后界面变化必须同步预览。
4. 对审查发现的问题先建立可复现证据，再做最小修复与适当回归；现行文档随实际行为更新。
5. 运行 Ruff、完整 Python 测试、生产 WebUI 与离线预览浏览器测试；再次审查新增改动。
6. 同步三个渠道，核对除版本与当前日志标题外的全部 Git 文件内容及模式，推送并等待三个目标提交 CI 全部通过。

验证边界：静态审查和模拟／本地测试不代表真实 Oopz 账号、模型服务或用户部署环境验收；报告明确区分已验证结果与限制。
