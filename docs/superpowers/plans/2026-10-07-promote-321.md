# Ooptra 三渠道 3.2.1 发布计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Execute inline with one release review at the end.

**Goal:** 将用户已完成测试的 dev 同步发布到 main、beta、dev，核对三个最新提交的 CI 全部通过。

**Architecture:** 在各渠道现有工作树中保留 Git 历史，以发布后的 dev 为同步来源。三个渠道的所有跟踪文件保持一致，仅 `src/core/version.py` 和 `CHANGELOG.md` 的当前渠道版本不同。

**Tech Stack:** Python、Git、pytest、Ruff、Playwright、GitHub Actions。

**Spec:** 用户本轮发布请求及下述明确约束。

## Global Constraints

- main：`3.2.1`；beta：`261007.2-beta`；dev：`261007.2-dev`。
- 三个渠道的正式版比较基线统一为 `3.2.1`。
- README 和两张无版本号 SVG 图片完全相同，不重新加入静态版本徽章。
- 保留既有代码功能、登录与共享 Token 修复、单处人格设置、更新进度条及日志默认换行。
- 不改本地部署配置、凭据和数据，不改 AstrBot 插件项目。
- 普通合并和推送，保留远程历史；CI 出错先定位原因，再修复并检查最新提交。

## Review Focus

- 带日内修订号的日期版本不得遮蔽后续正式版本更新。
- 三个分支当前版本和 CHANGELOG 首条版本对应正确；保存既有发布记录。
- beta/main 同步结果包含已测试的 dev 登录、维护和回归测试内容。
- 除两个版本元数据文件外，所有跟踪文件的 Git 对象均一致。
- 每个分支的 CI 对应实际推送的最新提交，所有任务成功，不将取消或旧记录视为通过。
